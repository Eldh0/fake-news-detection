# Fake News Detector

A beginner-friendly Fake News Detection web application that fine-tunes **DistilBERT** for binary text classification. The frontend is built with **Streamlit**, and the project reports real test-set metrics instead of hardcoded numbers.

- **Class 0:** FAKE
- **Class 1:** REAL
- **Model:** `distilbert-base-uncased`
- **Technique:** supervised NLP / transformer fine-tuning
- **Dataset:** [Fake and Real News Dataset on Kaggle](https://www.kaggle.com/datasets/clmentbisaillon/fake-and-real-news-dataset)

> This is an educational project. It does not verify facts, inspect sources, or browse the web. Predictions can be wrong.

**No-training route:** load the public fine-tuned model `therealcyberlord/fake-news-classification-distilbert` from the Hugging Face Hub. It was trained on the same Kaggle dataset and uses `0 = FAKE`, `1 = REAL`. No data download, Colab training, or model upload is needed.

**Full training route:** open the included [`colab_train_and_deploy.ipynb`](colab_train_and_deploy.ipynb) in Google Colab. It checks the GPU, mounts Drive, installs packages, trains, evaluates, uploads the model to Hugging Face Hub, and ends with deployment steps.

## 1. What the project does

1. Loads `Fake.csv` and `True.csv`.
2. Combines each article's title and body into one text field.
3. Removes empty rows, exact duplicates, and conflicting labels.
4. Creates a reproducible **80% training / 10% validation / 10% test** stratified split.
5. Saves the test split to `data/test.csv` and keeps it away from training.
6. Fine-tunes DistilBERT with Hugging Face `Trainer`.
7. Saves the best model to `saved_model/`.
8. Evaluates the saved model on the held-out test set.
9. Shows the real accuracy, precision, recall, F1-score, and confusion matrix in the Streamlit app.

### Main files

| File | Purpose |
|---|---|
| `train_model.py` | Cleans data, creates splits, fine-tunes DistilBERT, and saves the model |
| `evaluate_model.py` | Evaluates a local or Hub model on the test set, calculates metrics, saves charts |
| `app.py` | Streamlit frontend and inference |
| `colab_train_and_deploy.ipynb` | Ready-to-run Colab training, evaluation, and Hub upload notebook |
| `requirements.txt` | App-only deployment dependencies (PyTorch, Transformers, Streamlit) |
| `requirements-train.txt` | Additional training/evaluation dependencies |
| `.streamlit/config.toml` | Dark theme configuration |
| `.streamlit/secrets.toml.example` | Template for local/Hub settings; never commit real tokens |
| `.gitignore` | Keeps data, models, and secrets out of Git |

## 3. Dataset download and preparation

1. Open the Kaggle page: <https://www.kaggle.com/datasets/clmentbisaillon/fake-and-real-news-dataset>
2. Sign in to Kaggle if asked.
3. Click **Download** and unzip the downloaded archive.
4. Put the files here with these exact names:

```text
data/Fake.csv
data/True.csv
```

The files should be directly inside `data/`, not inside another nested folder.

The CSVs normally contain `title`, `text`, `subject`, and `date` columns. `train_model.py` uses only `title` and `text`; it creates the label itself.

### Duplicate articles and leakage

News articles are often republished by multiple outlets. If the same or a nearly identical article appears in both training and test data, the model may recognize it instead of learning general patterns. That makes test scores look better than they really are.

`train_model.py`:

- normalizes whitespace and capitalization before de-duplication,
- removes exact duplicate texts **before** splitting,
- removes texts that have conflicting labels,
- stratifies the split so FAKE/REAL proportions stay similar.

Near-duplicates can still exist (for example, the same story with a different title). For a stronger experiment, you could group near-duplicate articles with text-similarity or clustering and keep each group entirely in one split. That is an optional extension, not required for this project.

## 5. Train the model

Make sure the dataset is in place:

```text
data/Fake.csv
data/True.csv
```

Run:

```powershell
python train_model.py
```

What happens:

1. The data is loaded and cleaned.
2. Exact duplicates are removed.
3. The 80/10/10 split is created with random seed `42`.
4. `data/test.csv` is saved.
5. DistilBERT is fine-tuned for two epochs.
6. The best validation checkpoint is restored.
7. The final model and tokenizer are saved in `saved_model/`.

The first run downloads the DistilBERT base model (about 250 MB) from Hugging Face.

The script uses `Trainer` and `TrainingArguments`:

- `Trainer` is Hugging Face's ready-made training loop. It handles batching, GPU/CPU movement, backpropagation, evaluation, and saving checkpoints.
- `TrainingArguments` is the configuration object: learning rate, batch size, epochs, evaluation timing, and output folder.

Default training settings are deliberately small:

- 2 epochs
- batch size 8
- maximum sequence length 256
- learning rate `2e-5`

If you run out of memory, change `BATCH_SIZE = 8` to `4` in `train_model.py`. You can also lower `MAX_LENGTH` to `192`.

You should see validation accuracy, precision, recall, and F1 after each epoch. The test set is not used while training.

## 6. Evaluate the model

For the locally trained `saved_model/`:

```powershell
python evaluate_model.py
```

For the public Hub model instead:

```powershell
python evaluate_model.py --model therealcyberlord/fake-news-classification-distilbert
```

To evaluate a random sample on a slow CPU:

```powershell

```

Create the test split without training first if needed:

```powershell
python -c "import train_model; d=train_model.load_and_clean_data(); _,_,t=train_model.make_splits(d); t[['text','label']].to_csv('data/test.csv', index=False)"
```

This loads the model and the exact test split created by `train_model.py`. It calculates:

- Accuracy
- Precision
- Recall
- F1-score
- Confusion matrix
- Per-class metrics

It saves real results to:

```text
outputs/evaluation_metrics.json
outputs/confusion_matrix.png
outputs/classification_report.txt
```

It does **not** invent scores. If the required model or test file is missing, the script stops with a clear error.

When you evaluate the public Hub model, the script adds an `evaluation_note` to the JSON and the app displays a warning. The reason is that the public model was trained on the same Kaggle source dataset, so a random split of that dataset is not a clean held-out test for that model.

### What the metrics mean

Using REAL as the positive class:

- **Accuracy:** percentage of all test articles classified correctly.
- **Precision:** of the articles predicted REAL, how many were really REAL? High precision means fewer unnecessary REAL predictions.
- **Recall:** of all truly REAL articles, how many did the model find? High recall means fewer missed REAL articles.
- **F1-score:** a balance between precision and recall.
- **Confusion matrix:** shows correct and incorrect counts for both classes. The diagonal cells are correct predictions; the other cells are errors.

The app displays the saved metrics only when `outputs/evaluation_metrics.json` exists.

## 11. Why keyword matching is not enough

A keyword rule might flag words such as `secret`, `shocking`, or `report`. But the same words occur in reliable and unreliable writing.

Example:

- Real-style: "The annual report describes the new public-health policy."
- Fake-style: "A secret report proves that the new policy is a cover-up."

The word `report` appears in both. A keyword list cannot tell which sentence is trustworthy.

DistilBERT reads the sequence as a whole. It learns associations between words, word order, and surrounding context from labelled examples. For instance, it can combine patterns like "according to a report published by..." differently from "a secret report proves...".

However, DistilBERT only learns statistical patterns in its training data. It does **not** automatically check claims against external evidence. A confident prediction is not proof that a story is true or false.

## 13. Short explanation for your presentation / viva

**Problem:** Fake news spreads quickly, so we want an NLP system that estimates whether a news article looks fake or real.

**Dataset:** The Kaggle Fake and Real News Dataset contains two labelled CSVs. We assign FAKE = 0 and REAL = 1.

**Preprocessing:** We combine title and article text, handle missing values, remove exact duplicate articles before splitting, then create a reproducible stratified 80/10/10 split.

**Model:** We fine-tune `distilbert-base-uncased`, a compact transformer. The tokenizer converts text into word pieces. The model reads the sequence with attention and outputs two class scores. Softmax turns those scores into probabilities.

**Training:** Hugging Face `Trainer` handles the training loop. We monitor validation F1, save the best checkpoint, and keep the test set completely separate.

**Evaluation:** We use accuracy, precision, recall, F1-score, and a confusion matrix on the held-out test set. Precision asks how often a REAL prediction is correct; recall asks how many truly REAL articles were found. F1 balances the two.

**Frontend:** Streamlit loads the saved model once, validates the input, runs inference, displays FAKE/REAL with probabilities, and shows the saved evaluation metrics. The app does not retrain the model.

**Deployment:** Code is on GitHub. The model is on the Hugging Face Hub. Streamlit Community Cloud runs `app.py` and reads `MODEL_REPO_ID` from secure secrets.

**Limitations:** The model learns language patterns and dataset shortcuts. It does not verify facts or sources, and it can be wrong on satire, new topics, or unusual writing. Confidence is not truth.

### Likely viva questions

**Why DistilBERT instead of TF-IDF?**  
TF-IDF mainly captures word frequencies. DistilBERT uses context and word order, which helps with phrases where meaning depends on surrounding words. It is also a real pre-trained transformer model, as required by this project.

**Why not keyword matching?**  
The same words occur in both real and fake articles. Keyword rules are brittle, easy to game, and cannot understand context.

**Why remove duplicates before splitting?**  
If the same article is in both training and test data, the model can memorize it, giving misleadingly high scores.

**Why use a separate validation and test set?**  
Validation helps choose the best model during training. The test set is kept untouched until the final evaluation, giving a fairer estimate of performance.

**What does the probability mean?**  
It is the softmax probability for the predicted class. It reflects the model's confidence based on learned patterns, not the factual truth of the article.

**What are the main limitations?**  
Dataset bias, source/style shortcuts, near-duplicates, new events, satire, and the lack of external fact-checking.

## 15. Order of commands

### Public model route (no training)

```powershell
# 1. Setup
cd "C:\Users\WINDOWS\Documents\fake news detection"
py -3.11 -m venv .venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt

# 2. Make sure .streamlit/secrets.toml contains:
# MODEL_REPO_ID = "therealcyberlord/fake-news-classification-distilbert"

# 3. Run the web app
streamlit run app.py
```

### Train your own model

```powershell
# 1. Setup
cd "C:\Users\WINDOWS\Documents\fake news detection"
py -3.11 -m venv .venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements-train.txt

# 2. Put Fake.csv and True.csv in data/

# 3. Train
python train_model.py

# 4. Evaluate on the held-out test set
python evaluate_model.py

# 5. Run the web app
streamlit run app.py
```

The current `outputs/` files contain a reference evaluation of the public Hub model on 1,000 randomly sampled test rows. The app displays a warning because the public model may have seen the same Kaggle dataset during its own training. For a clean held-out result, train your own model or evaluate on external data. If you use the public model, clearly state that you did not train it.
